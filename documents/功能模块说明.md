## 1. 系统概述

**项目名称**：博士生生命周期管理系统（DTLMS Platform）

**所属机构**：上海人工智能实验室

**系统定位**：面向联培博士生全生命周期管理，覆盖招生报名、资料审核、导师初筛、初筛确认、入营名单、录取通知、学生主档、研究中心管理、培养方案、科研报告、外出研修、学位论文、盲审管理、审批流程、系统治理等环节。

**核心业务流**：学生门户注册 → 填报申请表 → 资料审核 → 导师初筛（第一/第二志愿） → 初筛确认 → 入营名单管理 → 录取通知发送 → 学生确认录取 → 入学建档 → 培养管理 → 学位管理。

## 3. 角色与权限模型

### 3.1 双轨认证体系

系统存在两套独立的认证体系：

| 体系 | 认证方式 | Token 存储 | 用户表 |
|------|----------|------------|--------|
| 管理后台 | 用户名/密码 → JWT Access + Refresh Token | `dtlms-access-token` | `dtlms_users` |
| 学生门户 | 邮箱验证码/密码 → Portal JWT | `dtlms-portal-access-token` | `dtlms_portal_students` |

### 3.2 RBAC 权限体系

管理后台采用基于角色的访问控制（RBAC）：

- **用户**（`dtlms_users`）→ **角色**（`dtlms_roles`）→ **权限**（`dtlms_permissions`）
- 关联表：`dtlms_user_roles`、`dtlms_role_permissions`
- 权限通配符 `*` 表示超级管理员，拥有全部权限
- 后端通过 `require_permissions(...)` 依赖注入校验权限
- 前端通过 `menuAccess.ts` 的 `MENU_ACCESS_ENTRIES` 控制菜单可见性

### 3.3 权限标识

| 权限标识 | 说明 |
|----------|------|
| `dashboard:read` | 经营总览 |
| `recruitment:read` / `recruitment:write` | 招生计划/资料审核 |
| `recruitment_registered_students:read` / `:write` | 注册学生管理 |
| `recruitment_advisor_screening:read` | 导师初筛 |
| `recruitment_initial_screening_confirmation:read` | 初筛确认 |
| `recruitment_camp_offer:read` / `:write` | 入营名单 |
| `news_management:read` | 新闻管理 |
| `students:read` / `students:write` | 学生主档 |
| `research_center:read` / `:write` | 研究中心管理 |
| `training:read` / `training:write` | 培养管理 |
| `degree:read` / `degree:write` | 学位管理 |
| `workflow:read` / `workflow:write` / `workflow_center_menu:read` | 流程中心 |
| `system:read` / `system:write` | 系统用户/角色/字典/集成 |
| `audit:read` / `audit:write` | 审计策略/操作日志 |

## 4. 功能模块详解

### 4.1 认证与个人空间

**后端文件**：`backend/app/api/v1/auth.py`、`backend/app/core/security.py`、`backend/app/core/rbac.py`

| 功能 | API 端点 | 方法 | 权限 | 说明 |
|------|----------|------|------|------|
| 管理端登录 | `/api/v1/auth/token` | POST | 公开 | OAuth2 密码模式，返回 Access + Refresh Token |
| 获取当前用户 | `/api/v1/auth/me` | GET | 已认证 | 返回 Principal（用户名、角色、权限） |
| 获取个人资料 | `/api/v1/auth/profile` | GET | 已认证 | 返回用户档案（姓名、部门、主题色等） |
| 修改个人资料 | `/api/v1/auth/profile` | PUT | 已认证 | 修改姓名、电话、邮箱、主题色 |
| 修改密码 | `/api/v1/auth/change-password` | POST | 已认证 | 校验旧密码后更新 |
| 退出登录 | `/api/v1/auth/logout` | POST | 已认证 | 注销会话 |
| 刷新 Token | `/api/v1/auth/refresh` | POST | 公开 | 用 Refresh Token 换取新 Token |

**前端页面**：
- `LoginView.vue` — 管理端登录页
- `ProfileView.vue` — 个人空间（资料编辑、密码修改、主题设置）

**业务规则**：
- 登录时记录 `last_login_at`（`dtlms_users` 表）
- 会话存储在 Redis（Sentinel 集群），Key 前缀 `CTDTLMS_`
- Access Token 有效期 1440 分钟（24h），Refresh Token 10080 分钟（7d）
- 操作审计中间件自动记录后台写操作（POST/PUT/PATCH/DELETE）到 `dtlms_operation_logs`

| 状态值 | 含义 | 触发方 |
|--------|------|--------|
| `NULL` | 待录取 | 初始 |
| `declined` | 未录取 | 中心负责人 |
| `pending` | 待定 | 中心负责人 |
| `accepted_pending_send` | 录取未发送 | 中心负责人 |
| `accepted_sent` | 录取已发送 | 书院管理员（发邮件后） |
| `accepted_confirmed` | 录取已确认 | 学生（接受） |
| `accepted_rejected` | 录取已拒绝 | 学生（拒绝） |

**不变量**：
- `student_submitted_offer_at` IS NOT NULL ⇔ `accepted IN ('accepted_confirmed', 'accepted_rejected')`（终态）
- 写终态时必须同时写 `student_submitted_offer_at = now()` + `updated_at = now()`
- `declined` / `pending` 状态不允许发送录取通知邮件

**邮件发送模式**（`SMTP_SEND_MODE`）：
- `mock`：收件人统一替换为 `lk139@126.com`（测试模式）
- `real`：使用学生真实邮箱（生产模式，默认）

**Offer 模板**：
- 系统内置模板：`offer.md`（第一志愿）、`offer2.md`（第二志愿）
- 支持上传 `.md` / `.markdown` 自定义模板（最大 1MB，UTF-8）
- 模板支持变量占位符渲染预览

**前端页面**：`CampOfferListView.vue`
- 筛选区：关键词、招生计划、是否发邮件、是否同意、夏令营选拔、第一/第二志愿导师/团队/评分范围
- KPI 卡片：按筛选条件实时统计
- 进度条发送录取通知（逐封调用 `/send-offer-notification/one`，显示已处理/总数/实际模式/实际收件人）
