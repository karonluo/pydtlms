# 20260603新闻信息管理开发计划

## 1. 开发目标

1. 在招生管理菜单下新增“新闻管理”入口。
2. 在系统字典中新增“新闻类型”，支持学生门户通知消息、学生门户新闻信息两类值。
3. 完成新闻管理列表的增、删、改、查能力。
4. 完成富文本编辑能力，并支持正文图片上传。
5. 新增新闻信息表及对应后端接口、前端页面、权限与字典支撑。
6. 先交付管理后台能力，学生门户联动展示留待后续需求补充后继续推进。

## 2. 当前需求确认

### 2.1 菜单结构

1. 招生管理下新增二级菜单“新闻管理”。
2. 新闻管理与现有招生管理子菜单保持同级关系，作为独立列表入口。

### 2.2 系统字典

1. 新增字典名称：新闻类型。
2. 字典值固定为：
   - 学生门户通知消息
   - 学生门户新闻信息
3. 新闻表中的类型字段直接引用该字典值。

### 2.3 页面功能

1. 新闻列表支持分页查询、条件筛选、详情查看、新增、编辑、删除。
2. 新增与编辑使用富文本编辑器。
3. 富文本正文支持上传图片并回填到内容中。
4. 新闻列表页应支持标题、类型、发布日期时间、发布者等基础筛选与展示。
5. 编辑页不再直接暴露状态下拉，新闻状态通过“保存草稿 / 直接发布”以及列表单行、批量发布/下线业务按钮驱动。

### 2.4 数据库存储

1. 新增新闻信息表，正文内容采用无限长度存储。
2. 至少包含以下字段：
   - 新闻标题
   - 新闻内容
   - 发布者
   - 审核者
   - 发布日期时间
   - 新闻类型字典值字段
3. 审核者字段先保留，不强制接入审核流程，但要为后续审核链路预留。
4. 结合现有项目习惯，补齐创建时间、更新时间、删除标记、发布状态或置顶排序等常用管理字段，具体以实现时最小必要集合为准。

### 2.5 交付边界

1. 本轮只做管理后台，不做学生门户展示。
2. 管理后台完成后，再根据学生门户需求继续扩展联动。

## 3. 开发范围

### 3.1 后端

1. 新增新闻信息表对应的模型、schema、service、API。
2. 新增图片上传或富文本附件上传所需接口与存储处理。
3. 新增新闻管理权限控制与接口校验。
4. 新增新闻类型字典初始化或增量脚本。

### 3.2 前端

1. 在招生管理菜单中新增“新闻管理”页面入口。
2. 实现新闻列表页、编辑抽屉或弹窗、删除确认与详情查看。
3. 集成富文本编辑器与图片上传能力。
4. 新闻类型字段接入系统字典下拉。

### 3.3 数据库

1. 新增新闻信息表。
2. 新增或补充系统字典数据。
3. 如需要，为图片、状态、排序、软删除等常用管理字段预留结构。

## 4. 推荐实施顺序

1. 先完成数据库表结构与字典设计。
2. 再完成后端增删改查接口与图片上传能力。
3. 然后完成前端菜单、列表页和富文本编辑页。
4. 最后补齐权限、联调、回归测试与 README 更新。

## 5. 验收标准

1. 招生管理下可正常看到“新闻管理”菜单。
2. 可正常维护新闻数据的增、删、改、查。
3. 富文本内容可正常保存与回显，图片可正常上传并展示。
4. 新闻类型可从系统字典正确选择并落库。
5. 数据库中已落地新闻信息表，且字段满足当前需求与后续审核扩展需要。
6. 新闻状态通过业务按钮完成发布与下线，支持单行和批量操作。
