## 1. 背景

当前招生管理中已有“导师初筛”“初筛确认”等入口，但尚未提供“入营名单”管理能力。

本次需求要求在“招生管理 -> 初筛管理”下新增“入营名单”菜单，用于通过 Excel 上传候选人名单，并在 `dtlms_plan_offer` 表中落库，再提供基础 CRUD 能力，作为后续“发邮件 + 学生点击链接同意/拒绝 Offer”功能的前置基础。

本轮只做“上传导入 + CRUD”，不做邮件链路与学生端 Offer 页面。

## 2. 目标

1. 在“招生管理 -> 初筛管理”下新增“入营名单”菜单与页面入口。
2. 支持上传 Excel 导入名单，且 Excel 必须包含 `candidate_no` 列。
3. 将导入结果写入 `dtlms_plan_offer`，当未提供 `plan_id` 时默认落到最新招生计划。
4. 提供入营名单列表与基础 CRUD（新增、查询、修改、删除）。
5. 列表展示字段固定为：
   - 报名号
   - 是否已发邮件
   - 数据创建日期（第一次上传时间）
   - 招生计划名称
   - 是否同意
   - 原因
   - 学生姓名
   - 学生提交日期（学生提交是否同意 Offer 的日期时间）

## 3. 当前冻结的需求理解

### 3.1 菜单与入口

1. 菜单位置：`招生管理 -> 初筛管理 -> 入营名单`。
2. 与“导师初筛”“初筛确认”同级，位于其下方新增。
3. 入口权限单独控制，不复用无关页面权限码。

### 3.2 导入规则

1. 导入文件格式：Excel（`.xlsx`）。
2. 表头必须包含 `candidate_no` 列；缺失则整单拒绝并提示。
3. 行级规则：`candidate_no` 为空的行跳过并记录 issue。
4. 导入成功后写入 `dtlms_plan_offer`。
5. `plan_id` 取值规则：
   - 若请求显式传入 `plan_id`，使用传入值。
   - 若请求未传 `plan_id`，自动使用“最新 `dtlms_recruitment_plans.id`”。

### 3.3 字段口径

1. 报名号：`dtlms_plan_offer.candidate_no`
2. 是否已发邮件：`dtlms_plan_offer.is_sent_mail`
3. 数据创建日期（第一次上传时间）：`dtlms_plan_offer.created_at`
4. 招生计划名称：`dtlms_recruitment_plans.plan_name`（通过 `plan_id` 关联）
5. 是否同意：`dtlms_plan_offer.is_agree`
6. 原因：`dtlms_plan_offer.reson`
7. 学生姓名：通过 `candidate_no` 关联报名申请表后取 `student_name`
8. 学生提交日期：`dtlms_plan_offer.submited`
   - 明确口径：该字段表示“学生提交是否同意 Offer 的日期时间”，不是报名表提交时间。

### 3.4 本轮边界（严格）

本轮包含：

1. 菜单、路由、页面入口。
2. Excel 上传导入。
3. 入营名单基础 CRUD 与列表展示。

本轮不包含：

1. 发送邮件给学生。
2. 学生点击链接进入同意/拒绝页面。
3. Offer 链接签名、过期校验、回调确认链路。
4. 任何超出 CRUD 的流程编排。
