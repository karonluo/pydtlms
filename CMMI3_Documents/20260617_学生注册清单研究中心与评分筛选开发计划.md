# 20260617 学生注册清单研究中心与评分筛选开发计划

## 开发状态

- [未开始] 第一步：冻结筛选口径与字段映射
- [未开始] 第二步：梳理 `/students/portal-registrations` 的查询、导出与前端参数入口
- [未开始] 第三步：实现第一/第二志愿导师所属研究中心筛选
- [未开始] 第四步：增加第一/第二志愿导师评分列并支持排序
- [未开始] 第五步：实现第一/第二志愿评分比较筛选
- [未开始] 第六步：补充单元测试、接口验证与前端构建验证
- [未开始] 第七步：同步更新相关需求文档、开发记录与上线材料

## 1. 背景

当前“学生注册”清单已经支持按关键词、报名状态、导师名单等条件筛选，但还不能直接按以下业务条件检索：

1. 第一志愿导师所属研究中心
2. 第二志愿导师所属研究中心
3. 第一志愿导师评分列及其排序
4. 第二志愿导师评分列及其排序
5. 第一志愿评分的比较查询
6. 第二志愿评分的比较查询

用户希望在注册学生清单中直接完成以上筛选，避免先导出再处理，也避免通过其他页面间接检索。

本次需求的核心是把“志愿导师 / 研究中心 / 评分”三类条件全部收敛到同一条服务端筛选链路中，让列表查询、分页和导出尽量保持一致。

## 2. 目标

1. 在“学生注册”清单中增加按“第一志愿导师所属研究中心”“第二志愿导师所属研究中心”的筛选能力。
2. 在“学生注册”清单中增加第一志愿导师评分列，并支持按该列排序。
3. 在“学生注册”清单中增加第二志愿导师评分列，并支持按该列排序。
4. 在“学生注册”清单中增加第一志愿评分的比较筛选条件，支持大于、大于等于、小于、小于等于、等于。
5. 在“学生注册”清单中增加第二志愿评分的比较筛选条件，支持大于、大于等于、小于、小于等于、等于。
6. 保证筛选逻辑走服务端，分页、导出和列表视图使用同一套口径。
7. 保持现有“学生注册”页面的整体结构和交互习惯，尽量只扩展筛选项，不重构整页。

## 3. 当前现状判断

### 3.1 已有基础

1. 后端注册学生列表入口已存在于 [backend/app/api/v1/students.py](backend/app/api/v1/students.py)。
2. 列表聚合逻辑已集中在 [backend/app/services/management_service_students.py](backend/app/services/management_service_students.py)。
3. PostgreSQL 查询层已能从真实库中读取团队、导师和学生信息，相关查询位于 [backend/app/services/postgres_state_store_query_students.py](backend/app/services/postgres_state_store_query_students.py)。
4. 研究中心主数据与导师关系已独立管理，中心表关联可从 `dtlms_users`、`dtlms_team_advisors`、`dtlms_teams` 直接查到。
5. 前端“学生注册”页已集中在 [frontend/src/views/students/StudentsView.vue](frontend/src/views/students/StudentsView.vue)，接口封装在 [frontend/src/api/students.ts](frontend/src/api/students.ts)。
6. 现有导出模板里已经包含第一志愿/第二志愿导师、评分、所属研究中心等列，说明导出侧已有基础字段承接能力。

### 3.2 当前缺口

1. “学生注册”列表当前还没有把“研究中心”作为独立筛选条件暴露给前端。
2. “学生注册”列表当前也没有把“第一志愿评分”“第二志愿评分”的比较符号和数值输入做成可查询条件。
3. 现有筛选参数主要还是围绕关键词、报名状态、导师名单，不能满足按中心和分数快速定位的业务需求。
4. 需要确认研究中心筛选是按“导师所属研究中心”过滤，而不是按学生所属中心或报名计划中心过滤。
5. 需要确认评分筛选只作用于注册学生清单，不额外扩散到其他管理页，避免范围外改动。

## 4. 范围说明

本轮只做以下内容：

1. 扩展“学生注册”清单的筛选参数。
2. 扩展后端查询条件与 PostgreSQL 查询逻辑。
3. 扩展前端筛选区与接口参数传递。
4. 补充测试与文档。

本轮不做以下内容：

1. 不改学生主档、研究中心管理、导师初筛、招生工作台的筛选规则。
2. 不改注册学生的报名提交流程。
3. 不新增与本需求无关的导出列、字段或业务状态。
4. 不重构整个学生管理页面，只做注册清单的定向扩展。

## 5. 开发步骤

### 第 1 步：冻结筛选口径与字段映射

怎么做：

1. 明确“第一志愿导师所属研究中心”“第二志愿导师所属研究中心”都以导师真实归属中心为准。
2. 明确研究中心的判断链路沿用导师到团队/中心的实际关系，不使用前端手填字符串。
3. 明确评分筛选只针对数值比较，不做模糊匹配，不做区间推断。
4. 明确空值处理规则：未选择中心或未录入评分时，不参与该条件过滤，避免误伤空数据。
5. 明确比较符号仅支持：大于、大于等于、小于、小于等于、等于。

当前已确认的数据库控制点：

1. `dtlms_users` 提供导师姓名和导师主键。
2. `dtlms_team_advisors` 提供导师与团队/中心的关联。
3. `dtlms_teams` 提供研究中心/团队名称及团队主数据。
4. `dtlms_recruitment_applications` 提供第一志愿、第二志愿及对应评分字段，其中第一志愿导师评分字段为 `first_choice_screening_score`，第二志愿导师评分字段为 `second_choice_screening_score`。

### 第 2 步：梳理查询入口与参数入口

怎么做：

1. 先确认后端 `GET /students/portal-registrations` 当前接收的参数集合。
2. 识别列表查询与导出查询是否共用同一条筛选逻辑。
3. 在 [frontend/src/api/students.ts](frontend/src/api/students.ts) 中扩展请求参数类型。
4. 在 [frontend/src/views/students/StudentsView.vue](frontend/src/views/students/StudentsView.vue) 中确认筛选区状态字段、下拉选项和重置逻辑。
5. 在 [backend/app/services/management_service_students.py](backend/app/services/management_service_students.py) 中补齐条件解析与 SQL 组装。

为什么这样做：

1. 先把入口梳理清楚，才能保证“列表筛选”和“导出筛选”不出现两套口径。

### 第 3 步：实现研究中心筛选

怎么做：

1. 增加“第一志愿导师所属研究中心”筛选条件。
2. 增加“第二志愿导师所属研究中心”筛选条件。
3. 后端根据导师姓名或导师主键，沿导师-团队关系反查所属研究中心。
4. 筛选条件与列表结果统一使用同一条查询链路，不在前端做二次过滤。
5. 研究中心筛选应支持空值不筛选，避免没有选中心时误排除数据。

实现重点：

1. 研究中心名称应来源于真实团队/中心表，不从导出文本反推。
2. 如果同一导师存在多个团队关联，需要明确选择规则，优先按当前主数据有效关系返回。

### 第 4 步：实现评分比较筛选

怎么做：

1. 增加“第一志愿评分”比较筛选框。
2. 增加“第二志愿评分”比较筛选框。
3. 前端提供比较符号选择和分数输入。
4. 后端把比较符号映射为数值比较条件，统一拼到服务端查询。
5. 保证比较值按数值处理，不按文本排序。
6. 第一志愿导师评分列和第二志愿导师评分列要直接展示在注册学生清单中，并支持列头排序。

实现重点：

1. 两个评分条件应彼此独立，可单独生效，也可同时生效。
2. 比较符号和分数为空时，不生成过滤条件。
3. 查询结果应与分页总数一致，避免只过滤当前页。

### 第 5 步：前端筛选区与接口联动

怎么做：

1. 在“学生注册”筛选区增加研究中心选择控件。
2. 在“学生注册”筛选区增加两个评分比较条件控件。
3. 在“学生注册”清单中增加第一志愿导师评分、第二志愿导师评分两列，并支持排序交互。
4. 调整查询参数组装与重置逻辑。
5. 确认分页切换、重置搜索、导出时都能携带当前筛选条件。
6. 如果页面已有类似筛选交互，尽量复用现有样式和布局。

### 第 6 步：补验证与文档

怎么做：

1. 补后端单元测试，覆盖中心筛选、评分比较筛选、空值场景、组合筛选场景。
2. 补前端构建或基础联调检查，确保筛选项不会破坏页面渲染。
3. 补相关需求文档与开发记录，保证本次口径可追溯。
4. 如筛选参数会影响导出，也补一条导出一致性验证。

为什么这样做：

1. 这是一个典型的查询口径扩展，必须把接口、页面、测试和文档同时补齐。

## 6. 验收标准

1. “学生注册”清单可以按第一志愿导师所属研究中心筛选。
2. “学生注册”清单可以按第二志愿导师所属研究中心筛选。
3. “学生注册”清单可以展示第一志愿导师评分列和第二志愿导师评分列，并支持排序。
4. “学生注册”清单可以按第一志愿评分进行比较筛选。
5. “学生注册”清单可以按第二志愿评分进行比较筛选。
6. 研究中心、评分筛选和排序支持组合使用，分页结果正确。
7. 空值条件不影响正常列表查询。
8. 列表查询与导出查询口径一致。

## 7. 风险与注意事项

1. 研究中心筛选依赖导师与团队的真实关系，若历史数据存在一对多或缺失关系，需要明确回退规则。
2. 评分筛选必须按数值比较，不能误按字符串比较导致排序或过滤错误。
3. 前端筛选项过多时，注意保持页面可用性，避免把“学生注册”页做成难用的查询表单。
4. 如果导出也要同步新增条件，必须确认导出和列表复用同一套服务端条件解析。
5. 排序字段要明确使用数据库字段 `first_choice_screening_score` 和 `second_choice_screening_score`，避免前端按展示文本排序。

## 8. 待确认点

1. 研究中心筛选希望使用下拉选择，还是支持输入检索。
2. 评分比较框默认是否显示“等于”，还是需要保留上次选择。
3. 研究中心筛选是否同时支持按第一志愿和第二志愿分别筛选，还是只允许单个条件。
4. 导出是否同步复用这三个新增筛选条件。
